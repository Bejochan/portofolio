The Engineering Challenge & Objective

Conventional game recommendation engines rely on rigid genre filters that fail to capture nuanced emotional intent, situational fatigue, or negative constraints (e.g., "fast-paced shooting, but absolutely no sword combat"). Building an LLM assistant to solve this in production faces two major bottlenecks: severe rate-limiting (HTTP 429 quota exhaustion) on cloud LLM tiers and high response latency destroying conversational immersion.

Architecture & Data Flow

  1. Conversational Stream: Client interacts via Server-Sent Events (SSE) for word-by-word streaming.
  2. Dual-Pass Prompt Orchestration: Generates editorial responses while extracting structured JSON parameters (mood, budget, 3D DNA coordinates) via a low-temperature deterministic pass (temp=0.1).
  3. 6-Tier Cascading Failover (Commit 9ed7315): Automatically cascades across gemini-3.5-flash → 3.6-flash → 3.7-flash → 3.8-flash → 3.5-flash-lite → flash-latest when encountering HTTP 429 errors.
  4. Stage 1 Fast Candidate Generation: Filters 24,082 games down to top 25 candidates using 3D Euclidean DNA distance, Jaccard genre similarity, and IDR budget constraints in < 50 ms.
  5. Stage 2 Neural LLM Re-Ranking: Validates granular nuances and negative constraints before rendering the top 6 games and dynamic SVG DNA radar charts.

Key Technical Contributions

  • Intercepted HTTP 429 quota exhaustion with a 6-tier cascading failover engine, ensuring continuous uptime.
  • Built graceful degradation mode utilizing accumulated session DNA scores and friendly user messaging if all cloud tiers are unavailable.
  • Designed zero-dependency frontend streaming parser using ES6 ReadableStream with dynamic client-side SVG radar visualization.

Measurable Metrics

  • Failover Depth: 6-Tier Cascade Resilience
  • Vector Retrieval Latency: < 50 ms across 24,082 games
  • Curated Catalog: 24,082 games with live Steam IDR pricing
